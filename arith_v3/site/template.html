Behavior-Probe

Can a model work out how one particular student gets arithmetic wrong, across all four operations, then predict that student's next answers?

Each task shows a few answers from one simulated student who follows hidden, systematically buggy rules for addition, subtraction, multiplication or division. The model must predict exactly what that student will write on 40 or 80 new problems. Reproducing correct arithmetic earns nothing on the questions that count.

Method

The task

A simulated student does arithmetic column by column but follows fixed, rule-governed errors, such as forgetting to decrement after borrowing, dropping a carry or reading a 1 as a 0. The model sees a handful of that student's answers and the test problems, and writes a JSON file with a predicted answer and a confidence for each.

Three levels

  • Level 1, one operation. Easy tasks have one bug and six examples. Hard tasks combine two interacting bugs and show four examples chosen so that many rule pairs fit them. 40 test problems.
  • Level 2, mixed. A different hidden bug in each of the four operations, two examples per operation. 80 test problems.
  • Level 3, transfer. One misreading of digits applies to every operation. The four examples cover three operations; the fourth, the target, has none. 80 test problems.

The error types are 12 of the 17 numbered categories in Wallace (1984), plus her supplementary "smaller from larger". Their exact algorithms and triggers are our own operationalization.

Optional probes

In the probe setting the sandbox also has a probe OP A B command that returns this student's answer to any new problem, up to 10 times, and a snapshot command that saves the current predictions without revealing a score. Test problems cannot be probed. Using either is left entirely to the model.

Scoring

  • A prediction is correct only if it equals the student's answer exactly. There is no partial credit and no model-based judging.
  • Half of the test problems are ones the student gets wrong. The headline accuracy counts only those, since any model that can do arithmetic gets the other half.
  • A submission that omits a question or is malformed scores 0 for that task.
  • The oracle reference keeps every rule in the benchmark's hypothesis family that fits the examples and answers by majority vote. It shows what the evidence allows; it is not an upper bound.

Setup and limits

  • Each model runs in its vendor's agent harness (Claude Code or Codex CLI) on Valkyrie, in a Modal sandbox with a 30-minute limit and network access only to its model API. The hidden rules live in a separate oracle container; the grader and answer keys arrive only after the agent finishes.
  • Every cell is a single run over 20 students. Treat gaps smaller than the ± column as noise.
  • All four Level-3 tasks use the same hidden rule, so Level 3 measures one shared misreading, not transfer in general.
  • The students are simulated. Results show whether a model can identify a rule-governed error pattern, not how it would model real children.

Behavior-Probe is an independent benchmark and is not affiliated with any model provider. The earlier subtraction-only version is at /v1.
